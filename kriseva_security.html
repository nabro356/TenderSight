Principles

What local-first actually means here.

TAS is designed around local database, local file storage, local document processing, and local model routes where configured. External portal access, model integrations, calendar/email integrations, and deployment-specific connectors should be reviewed per deployment boundary.

01

Operator-controlled storage

Tender bundles and operator data live on local storage by default. The deployment owner controls retention.

Inside the boundary · default

02

Local model routes where configured

Local model routes are available where configured for active pilot workflows. Cloud routes are explicit, not default.

Inside the boundary · configured

03

Explicit external boundary

Portal calls, hosted model routes, and integrations cross the boundary only when configured, and they are documented.

Across the boundary · documented

04

Operator authority

KRISEVA recommends; the operator decides. There is no autonomous action against any portal.

Operator decides · no autonomous action

Boundary

The boundary is documented, not assumed.

Treat the diagram as the operating contract. Anything inside the local boundary stays local by default. Anything outside it is explicit, configured, and reviewed.

Inside the boundary SOLID · DEFAULT LOCAL

By default, local.

  • Tender bundle storage Local file storage on the operator’s machine / deployment node.
  • Tender database Local database. Tender records do not leave the deployment by default.
  • Document processing Local parsing for PDF, DOCX, XLSX, TXT, CSV.
  • OCR (where supported) Local OCR for scanned / low-text PDFs. OCR quality under active evaluation.
  • Model routes Local model routes available where configured for active pilot workflows.
Across the boundary DASHED · DOCUMENTED & CROSSABLE

Explicit, configured, reviewed.

  • Portal access (e.g., GeM) Network call to the configured portal. Behavior depends on portal session and availability.
  • Hosted model routes Used only when explicitly configured. Cloud model routes are not the default.
  • Calendar / email integrations Optional, deployment-specific. Off by default.
  • Deployment-specific connectors Reviewed per deployment boundary; not assumed.
Boundaries on Claims

What we will not call this.

Local-first is a design posture, not a security guarantee. Defense procurement deserves precise wording, not marketing claims.

  • NOT A no-egress data guarantee.
  • NOT An isolated-network deployment posture.
  • NOT An absolute-security claim.
  • NOT Encryption marketed with grade-style adjectives.
  • NOT A risk-free deployment promise.
  • NOT Any agency endorsement or defense-side validation.
Operator Surface

The boundary is visible from the settings surface.

Where the deployment crosses the boundary, the surface that controls it is operator-visible. No silent network calls.
